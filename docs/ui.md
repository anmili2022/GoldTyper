# 插件 UI 与验证说明

本文记录 `Windows/DebugWindow.cs` 的当前行为，最近更新于 2026-10-28。小游戏 addon 的结构与输入方式另见 [P0 调研模板](ui-structure.md)。

当前已删除防 AFK 活动输入、实验性 Hook、计时采集、配置字段和全部对应界面。自动答题等待结束后直接原生填入并提交，不发送随机字母或系统键盘事件，不检查游戏是否为前台窗口。下文涉及这些已删除功能的内容仅为历史排查记录，不代表当前实现；移除后的完整流程仍待实机回归。

## 运行控制

运行状态由 `GameAutomation` 管理，配置中已移除 `启用自动完成` 字段。

| 操作 | 可用条件与结果 |
| --- | --- |
| 加载插件 | 初始化为 `Idle`，不自动开始 |
| 开始 | 在 `Idle`、`Done`、`Error` 时可用；清空题目、取消暂停并进入 `Detecting` |
| 暂停 | 在 `Detecting`、`Typing`、`Submitting` 时可用；设置暂停标记，保留当前状态与题目 |
| 恢复 | 暂停后显示；清除暂停标记并保留当前状态 |
| 停止 | 始终可用；取消暂停、清空题目并返回 `Idle` |
| 关闭窗口 | 仅隐藏界面，不调用停止；需要结束运行时先点击“停止” |
| 重新打开窗口 | 显示现有运行状态，不自动开始 |

点击“开始”后在游戏线程每 100 ms 检测小游戏，选定目标后计算一次等待时间：现有输入间隔最小值至最大值的随机值，加上 Unicode 字符数 × 每字追加耗时，总计限制在 500–30000 ms。动态延迟默认开启，每字默认追加 180 ms，可关闭或调整；保留用户原有间隔配置，不新增独立基础间隔或抖动参数。目标身份或文字改变时重新计时。等待结束后执行已启用的活动输入，随后填入答案，在同一次更新中立即调用原生 Enter 回调。提交后等待输入清空，仅表示回调已处理，不表示成功加分；下一题选定后再计算等待，不额外叠加一轮间隔。活动输入和帧采样另计耗时。结算窗口就绪且可见时进入 Done，阶段暂不可输入时返回检测。长度延迟变更待实机验证。

参考本机 FFMoGuang 的控制器与原生输入实现，目标按节点身份与文字跟踪，优先选择已提交次数较少、文字较短的可见词条。同一目标允许重复提交，最多 5 次，目标消失后清理计数；全部达到上限后进入 Error。输入 addon/控件身份变化时停止，避免把上一界面的操作带入新界面。可见性同时检查祖先隐藏标志、禁绘标志和透明度。

自动填入要求输入框为空，调用 SetText 后同时校验 RawString 和 EvaluatedString，防止截断或格式改变。提交使用独立 UTF-8 缓冲区，回调返回后重新查询控件再处理清空，不继续使用回调前指针。手动改字、提交后输入不清空、原生回调异常均停止。暂停、停止或目标消失时只清理相同会话中仍与插件填入文字相同的内容，不清除已被用户修改的文字。手动填入/发送会先停止自动流程。

## 页面

配置 Version 3 将防 AFK 活动输入、读条优先和近距离优先的默认值统一设为开启；旧配置首次迁移时也开启这三项并保存，之后保留用户手动修改的开关状态。此处覆盖下文较早记录中的默认关闭说明。

自动页新增“AFK 计时（客户端参考值）”卡片，游戏线程随正常快照约每 100 ms 只读采集 InputTimerModule，即使两种防 AFK 都关闭或自动流程停止也可观察。展示自动离席、副本无输入、一般无输入的已计时值和对应阈值；阈值为正且计时非负时显示 max(0, 阈值 − 计时) 剩余秒数，剩余不超过 10 秒使用警告色。负计时显示特殊状态，非有限值、未启用阈值及空指针不生成倒计时。计时值随快照导出，但不加入变化历史签名，避免每次计时变化挤占历史。此为客户端参考值，尚未证明与魔光键影 AFK 判定一致；Hook 开启时计时可能接近零。Release 构建通过，实机读数与效果待验证。

因用户反馈打开窗口后游戏无响应，恢复版暂时断开 GameAutomation 中的 AfkHook.Update 调用和快照中的 AfkTimerSnapshot.Capture 调用。Hook 选项禁用并显示停用说明；旧配置保留但不会安装 Hook，计时卡片提示采集已停用。此为隔离措施，尚未确认卡死根因，也未确认恢复版游戏内表现。必须退出原有游戏进程再加载新构建，不能用新 DLL 假定已解除旧进程里的原生调用阻塞。下文 Hook 与计时采集说明为此前实验实现记录，当前暂不生效。

AFK 卡片补充采集序号和采集时间、Hook 累计调用次数、实际重置正计时值的帧数及最近一次重置前的三项读数。计数累计至插件卸载，关闭 Hook 后保留历史计数。用于区分采集停滞、Hook 未调用和计时被归零；通用计时器不变不能证明小游戏防 AFK 有效。此诊断补充仅通过离线构建，实机行为待验证。

选项页输入参数提供“启用防 AFK 活动输入”开关，默认开启以保留已有行为，修改自动保存。关闭后跳过每次答题前的随机字母与实体回车，正常答案仍填入后立即提交。运行中关闭时在下一次游戏线程更新中释放插件持有的按键，并按会话和原始文字精确匹配清理已确认的活动字符；首页显示活动输入已关闭。说明使用悬停提示，防 AFK 实际效果仍待验证。

新增第二个独立选项“启用防 AFK Hook（实验性）”，默认关闭并持久化保存，首页显示 Hook 状态。使用本机国服 FFXIVClientStructs 的 Framework 虚表 Tick 函数地址安装 Hook，不使用猜测的字节签名。仅在自动运行、未暂停、KTGInput 就绪可见且 AtkValues[2] 允许输入、KTGResult 不可见时，将 InputTimerModule 的 AfkTimer、ContentInputTimer、InputTimer 正有限值归零，再调用 Original；不修改负计时值或时间限制，不发送实体按键。暂停、停止、关闭选项或下一次采集确认离开可输入阶段后撤销 Hook，卸载时释放。异常停止干预并报告错误，detour 始终调用 Original。两个选项可以同时开启；单独验证 Hook 时应关闭活动输入。Release 构建通过，不代表小游戏 AFK 判定已验证；需实机观察超过 60 秒及暂停、停止、结算和卸载行为。

界面说明统一改为悬停提示：页面标题右侧的 `(?)` 显示页面说明，选项、滑块、入口 NPC 记录按钮、快照按钮和诊断控件悬停显示相应说明。移除常驻说明段落以缩短页面；运行状态、数据、错误及操作结果仍直接显示。入口 NPC 名称在记录按钮的提示中查看。

输入间隔默认 `500–5000 ms`（0.5–5 秒），选项范围为 500–30000 ms；旧配置迁移到 Version 2 时最小值设为 500 ms，保留最大值。该范围作为词条等待的基础随机间隔，动态延迟开启时追加每字耗时，填入后立即发送。输入清空等待超时为 5 秒；填入失败超过配置的重试次数后进入 Error，其余输入一致性或会话错误立即停止。失败重试默认 `3` 次，调试日志默认关闭。该节奏不代表已确认此前被退出的原因。

每次自动答题前执行一次活动输入：词条稳定且输入框为空时聚焦 KTGInput 节点 7，随机选择一个英文字母（a–z，避免连续两次相同），通过 Windows SendInput 按下对应实体键扫描码，至少跨过一次 100 ms 采集更新后释放。必须在 1500 ms 内实际读到该字母（允许大写），再按下实体回车键并跨帧释放，确认提交后输入为空才允许填入答案并立即提交。不使用退格键，不再按 20 秒周期执行，也不将全程空白视为成功。活动输入期间暂停填词与提交，不修改计时器内存。仅在游戏前台、输入窗口可见且允许输入、结算不可见时操作；按住 Shift/Ctrl/Alt、任一字母键或回车键时等待。文字异常、界面重建、字符未到达或系统输入失败时停止。暂停、停止、界面不可输入和结算会释放插件持有的按键；已观察到的活动字符在同一会话且文字完全匹配时清理，不删除其他文字。按键事件尚未处理便暂停时仍可能留下字符，恢复前需检查输入框。调试日志记录选择的字母、实际字符和提交清空结果。额外提交字母是否影响成绩及 AFK 计时器刷新效果仍待实机验证；需观察超过 60 秒，收到字符或输入清空不等于计时器已刷新。

“恢复默认参数”恢复输入间隔、词条长度延迟开关与每字耗时、失败重试次数。选项修改会保存到插件配置。

最近运行记录保留当前窗口实例观察到的最近 6 条 `Done` / `Error` 记录，首页成功率按这些记录计算，无记录时显示 `--`；会话日志最多保留 8 条。记录不持久化，重载插件后清空。自动终态判定尚未接入，因此目前正常操作不会产生已完成的小游戏记录。

聊天发送支持点击“发送”或在输入框按 Enter，使用 `ECommons.Automation.Chat.SendMessage`。节点点击使用 `AddonClicker` 派发原生 `ButtonClick`。这两个工具会实际操作游戏，不受自动化开始 / 暂停状态限制。

聊天发送与节点点击收进默认折叠的“备用工具（聊天发送 / 节点点击）”，展开后可继续使用，配置与实现保留。

实时诊断默认关闭，通过“开启只读采集（100 ms）”独立控制。在 `Framework.Update` 上读取当前加载周期的 addon 和节点，不跨帧保留原生指针。显示输入与结算窗口可见性、得分、耐久、输入候选状态字段、实际读取耗时、可见词条路径，以及输入组件类型、路径、可见性和清理 SeString 后的文字。结算可见性与输入状态字段分开显示，状态字段归零不代表整局结束。

每条可见词条旁提供“复制”和“填入”。复制写入系统剪贴板并回读校验；填入请求在下一次游戏线程更新时执行，重新查询 `KTGInput` 节点 `7`，仅当窗口就绪且可见、输入状态允许、无可见结算窗口并且原生类型检查确认是文本输入控件时调用 `SetText`。界面显示调用结果；当前尚未验证游戏是否接收该调用，也不自动提交，需要手动 Enter。该操作独立于自动运行开始/暂停，只在用户点击时执行。

用户已在游戏中确认填入成功。新增独立按钮“发送当前已填入文字”：在游戏线程重新校验上述条件以及输入非空、回调与所属 addon，调用输入控件原生 Enter 回调，传入当前 RawString、EvaluatedString 和 CallbackEventKind；回调要求清空时调用 SetText 清空。按钮只提交当前控件文字，不重新填入词条。发送功能已通过 Release 构建，实际提交与得分变化待游戏内验证。

诊断关闭窗口后继续，取消勾选或卸载插件时停止。自动运行的停止/暂停不影响独立只读诊断。最近 300 次数据变化保留在内存，可复制为 JSON；记录含词条、输入节点文本和原始字节，不包含结算玩家名单，不自动写入磁盘。清空记录不会停止采集。新增诊断通过 Release 编译；100 ms 采样、可见性过滤、候选文本及采集耗时仍待游戏内验证。

## 本轮验证（2026-10-28）

活动字符校验修复：实机日志显示实体字母输入的 RawString 带有 SeString 格式载荷，直接与单个字母比较会在 Enter 前误报“文字被修改”。现解析 SeString.TextValue 校验可见字母，保留完整 RawString 作为清理时的精确匹配依据。提交清空与 AFK 刷新效果待实机回归。

针对实体回车释放后 1500 ms 仍未清空的反馈，增加一次原生 Enter 回调兜底。仅在会话未变化、可见文字仍为预期单字母、实时原始文字与已观察活动文字完全一致时调用 InputDriver.Send，并校验 EvaluatedString 与该可见字母一致；之后再次等待最多 1500 ms 确认原始输入清空。文字异常、会话重建、提交失败或再次超时仍停止，不重复提交。日志记录兜底触发及原生回调结果；确认清空仅表示可继续答题，不代表实体回车被游戏接受或 AFK 已刷新。此修正需实机回归，也不能排除两次提交均被处理的可能。

每轮结算自动生成 UTF-8 文本简报，保存在插件配置目录的 `reports` 文件夹，通过选项页按钮打开。正文包含角色名@归属服务器、开始时间、结束时间、本人结算总分和用时。每个角色使用固定的 `角色名@服务器.txt` 文件，新一轮记录追加到文件末尾，各轮以空行分隔，不覆盖已有记录；文件名非法字符替换为下划线。此前按时间生成的旧简报保留，不自动合并或删除。按结算玩家名匹配本人行，未取得本人总分时等待，不拿其他玩家得分代替。首次观察到本轮可输入时开始计时，首次结算可见且本人总分可读时保存，每次结算只保存一次；中途重载只统计采集时段，未采集到开始则标为未知。只读观测独立于自动运行与诊断开关。新增功能通过 Release 构建，实际结算匹配与文件追加待游戏内验证。

调试日志已接入自动流程：启用后记录状态信息变化、填入/提交处理、活动输入与再次参加信息；Error 停止及读取/执行异常始终记录。异常停止保留原始原因，避免统一覆盖为“已停止”，并在聊天栏提示。Error 停止现场包括窗口可见性、输入状态字段、得分、耐久、会话、输入内容和目标身份。日志位于插件配置目录 `automation.log`，超过 2 MiB 轮换为 `automation.log.previous`；内存保留最近 200 条，在状态页显示并可从选项复制。记录可能包含当前输入的游戏文字，不包含聊天或账号信息；写入失败会在选项显示。新增日志功能通过 Release 构建，实际停止原因待采集。
