## 5. 其他发现

- 准备阶段，聊天仍为 `/party`，`ChatType = 2`、`TemporaryChatType = -2`，临时命令为空。此时尚不能确定小游戏是否使用专用聊天频道。
- `TextCommand` 中的 `/goldsaucer` 是打开金碟资料窗口的命令，不能当作小游戏频道。
- 当前 FFCS 的 `ChatChannel` 枚举不完整，不能直接作为所有可用聊天频道的列表。
- 部分 `AtkTextNode.NodeText` 的 `StringLength` 为 `0`，但 `BufUsed` 和原始缓冲区含有效文字。MCP 通用字符串解码会将其显示为空；只读采集已通过校验 `StringPtr`、`BufSize`、`BufUsed` 后读取缓冲区取得文字，不能据此误判没有题目。
- `AtkValues` 的 SeString 不能只按普通 UTF-8 字符串解析。后续实现需保留并解析载荷，避免控制字节或替换字符混入题目。
- 准备窗口可见时 `VisibilityFlags` 为 `0`。后续窗口检测不能仅凭这个字段判断可见性，需使用目标 API 的可见性与激活状态判定。
- 所有地址仅对当前进程有效，文档不保存可直接复用的绝对地址。
- 已在通用 UI 上验证递归采集可以取得组件内的文本路径（例如 `_DTR` 的 `16/2`）；该验证不等于已取得小游戏词条。改进后的采集器校验 addon 名称，组件递归限制深度与节点数量，并同时保存采集起止时间。下一轮只持续采集词条、输入、得分和耐久四个 addon，减少无关读取。
