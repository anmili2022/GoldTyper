## 5. 其他发现

### 2026-10-28 AFK 更新函数只读反汇编

- 已重新发现 MCP 的 `mem_read`、`object_access` 工具定义，并确认同一游戏进程正常响应。仅小范围读取机器码、指针及服务属性，没有调用原生函数、写内存或安装 Hook。
- 在当前客户端版本中，通过 `UIModule` 内嵌 `InputTimerModule` 偏移 `0xA9108` 定位计时对象。其构造函数位于游戏模块 RVA `0x9BC820`，不能将构造函数或虚表析构槽当作更新入口。
- 更新函数候选位于 RVA `0x9BCC40`。代码保存第二参数 `xmm1`，在满足状态条件且未检测到相应活动时，将该值累加到对象 `+0x14`、`+0x18`、`+0x1C`；另有状态分支同时清零这些字段。第二参数符合帧时间用途，但尚未动态验证调用约定。
- `ContentInputTimer (+0x14)` 的三条分支分别比较 `+0x28`、`+0x2C`、`+0x30`，已采样值为 `600 / 120 / 1800` 秒。分支由另一函数的返回值选择，尚未取得该返回值与当前小游戏的动态对应关系。不能把其中某条分支直接称为魔光键影的判定。
- 超过对应阈值时调用 RVA `0xC29AD0`，随后将 `ContentInputTimer` 设置为 `-1`。后续处理先检查状态及副本对象，再分派至副本处理；其中内容副本路径通过 RVA `0xB6D3A0` 分派事件 `0x333`。事件语义及与约 60 秒踢出的关系仍未验证。
- 更新候选入口已存在跳转补丁。只读追踪发现运行时桩、委托对象及继续转发的分派代码，符合托管委托调用链；仍未确定所属插件或最终业务方法。没有卸载、改写或叠加该 Hook。计时为 0 既可能由原生状态分支产生，也可能受现有 Hook 或实际输入影响，不能仅凭静态样本归因。
- `GetContentDirector` 的机器码仅为读取 `EventFramework +0x158` 后返回；此前卡死不能仅按调用时间归因于该函数。当前调研继续使用直接字段读取，不恢复原生调用。当前副本头部 `ContentId=57001`、`Sequence=1`，已知起止时间字段均为 0，不构成小游戏倒计时证据。
